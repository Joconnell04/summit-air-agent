# 004. Call control and phone numbers

Researched 2026-11-02. Free tools (WebSearch, WebFetch, curl), plus 2 Exa content reads for one Twilio page that blocks fetching ($0.004 total). Numbers are SOURCE (linked in section 6), MEASURED or ASSUMED.

## 1. Question

Can our server, not the model, stop the agent from hanging up or transferring a call until the gas and CO lines are said and staff are flagged, on LiveKit and on Retell? Can Twilio act as a backstop that works for either? And which one phone number should the agent answer, for calls and for booking-confirmation texts?

## 2. Why it matters to Summit Air

`docs/brief.md` and `docs/spec.md` are still stubs, so this ties to `docs/assignment.md` (a phone number Revin can call, a gas smell is urgent) and `docs/considerations.md`: C-12 (end-call and spam paths refuse until the safety script was said and a person flagged), C-11 (warm transfer to staff), C-08 (SMS confirmation), C-38 (one number, failover). `docs/decisions/04-voice-platform.md` recommends LiveKit with Retell standby, assumes the failover works, and could not read Retell's transfer page; this closes both.

## 3. Options

**Facts, by question**

1. **Retell.** A custom function cannot end or transfer a call; its reply goes back to the model as text. The End Call tool is opt-in ("the agent won't end calls on its own"), so leaving it out removes the model's hang-up. Agent timeouts (silence, max duration) and voicemail hangup still end calls. Our server can kill a call with `POST /v2/stop-call/{call_id}`, a kill switch and not a veto. Transfer Call (cold by SIP INVITE or REFER, warm, agentic warm) has no webhook to approve or veto it. In conversation flows, edges can use equation conditions on dynamic variables that are "deterministic ... no LLM involved", and a function's JSON reply can be saved as variables; the docs do not show the two combined, so that is unverified. The one hard server gate is the custom-LLM WebSocket, where our reply sets `end_call` and `transfer_number`, but then we run the model.
2. **LiveKit.** Hang up by deleting the room (sends the BYE; leaving the room does not hang up) or removing the SIP participant. Cold transfer is `TransferSIPParticipant` (SIP REFER; the Twilio trunk needs transfer and PSTN transfer enabled; on failure the caller stays in the room). Warm transfer needs an outbound trunk. The built-in `EndCallTool` has callbacks but no hard check, so we skip it and write end and transfer tools that ask the server first. After a worker crash the call stays up in a silent room, so the worker needs a fallback.
3. **Twilio REST as a gate: no, for trunking.** Twilio support: setting `Status=completed` on an Elastic SIP Trunking call "does not terminate the SIP call"; only our SBC or the carrier sending a BYE does, inbound or outbound. Plain Programmable Voice calls can be redirected or ended by REST, but LiveKit's TwiML route has no REFER.
4. **The 678 number.** MEASURED 2026-11-02 (`GET /v2/list-phone-numbers`): `+16783366730`, type `retell-twilio`, area code 678. Retell staff (2026-01-07): "it's not possible to move retell-twilio numbers to twilio"; no port-out is documented. It serves Retell only. Callers dial what they are given, so 678 matters on texts, callbacks and the website. Evidence that local codes raise answer rates is vendor-only (1.13x to 4x); that NYC homeowners distrust a Georgia code is ASSUMED.
5. **New Twilio number.** Manhattan: 212, 646, 332. Other boroughs: 718, 347, 929; 917 covers all five; 465 overlays the outer boroughs. Live stock by code is not verified (no Twilio login here). Prices (SOURCE, Aug 2026): local number $1.15/mo, toll-free $2.15/mo; trunk inbound $0.0034/min local, $0.013 toll-free; SMS $0.0083 per segment plus about $0.004 carrier fee. Texting needs A2P 10DLC: brand $4.50 (sole proprietor or low-volume standard) or $46, $15 non-refundable campaign vetting, then $1.50 to $10/mo, up to 5 business days. Toll-free verification is free, 3 to 5 business days, and unverified toll-free numbers are blocked. Voice on the trunk and SMS from our server on one number should work, since Twilio ignores a trunk number's voice URLs and `sms_url` is a separate field (ASSUMED; test one text each way).
6. **Retell on our Twilio number, with failover.** Import works: origination `sip:sip.retellai.com`, give Retell the termination URI, run Test SIP Connection. Twilio allows 10 origination URIs, lowest `priority` first, and fails over only on a failed session: not on 2xx, 400, 404, 405, 410, 416, 482, 484, 486 or 6xx; with no SIP response, after 4 seconds. So C-38's "4 s" holds only for a dead SIP endpoint, and if LiveKit answers but our worker is down there is no failover (ASSUMED from community reports of calls answered into silence). A health check could set the URI's `enabled` field via the Trunking API (field exists; unproven).

**A. New NYC Twilio number, one trunk, LiveKit priority 1, Retell priority 2.** Gate in each stack: LiveKit tools call a server `/gate/exit`; Retell runs with both built-ins off and equation edges. Effort about 2 to 3 days plus the 10DLC wait (ASSUMED). Cost $1.15/mo, $0.0034/min, about $20 one-time. Risk: the Retell equation test, 10DLC rejection, the failover gaps above.

**B. Keep 678, Retell only.** Least effort, but the number cannot move, so LiveKit is out. Retell's SMS add-on is $20/mo per number plus $0.01 per text and a 2 to 3 week review (SOURCE). Weakest on C-11 and the engineering story.

**C. Twilio Programmable Voice hop** (webhook returns `<Dial><Sip>` to either stack). Our server can end or redirect any call by REST. Costs $0.0085/min plus a $0.004/min SIP leg (SOURCE), adds a hop and a single point of failure, and cold transfer becomes a TwiML redirect.

**D. Retell custom-LLM WebSocket** as the standby. The server owns `end_call` and `transfer_number`; high effort, and we run the model.

## 4. Recommendation, and what would change it

The number: buy a new NYC local number on our own Twilio account (646 or 212 if in stock), one Elastic SIP trunk, LiveKit first and Retell second, and send the confirmation texts from the same number. Keep 678 as a Retell-only test line. The gate: put it in our own code. On LiveKit the worker has no model-callable hang-up or transfer except our tools, which refuse until the server says the safety line was said and staff flagged; Twilio cannot do this for trunk calls. On Retell, drop the built-ins, gate with equation edges, and treat stop-call as a kill switch. Add a health check that disables the LiveKit URI.

This changes if: the equation-edge test fails (Retell becomes a no-transfer fallback, or option D); the 10DLC campaign is rejected for a fictional business (use toll-free for texts); a test call shows no failover when the worker is down (cut over by hand); or a platform-proof gate matters more than latency (option C).
