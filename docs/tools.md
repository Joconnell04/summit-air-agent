# Tool contract

The interface between the voice layer (LiveKit worker or the Retell baseline) and the tool server. Every build lane codes against this page, so the lanes can run in parallel. The model asks; the server decides (docs/architecture.md).

## Envelope

Every endpoint returns HTTP 200 with:

```json
{"ok": true, "say": "One sentence the agent can say", "data": {}, "refused": null}
```

- `ok: false` with `refused` set (`gate_read_back`, `gate_safety`, `out_of_area`, `zip_not_heard` (the ZIP given to `check_service_area` or `read_back` was neither said by the caller on this call or a linked one, digits or words, nor on a matched customer's record, nor found by `find_address` for a street the caller said), `zip_mismatch` (the caller's ZIP disagrees with the one lookup match for their street; `say` reads back the address the lookup found and asks which ZIP is right, the voice layer speaks it as written, and `check_service_area`, `read_back` and `book_appointment` refuse that ZIP until the caller says it again after the question or picks the lookup's ZIP; an address on a matched customer's record with that ZIP is never questioned), `customer_type`, `limit`, `not_owner`, `fsm_unavailable`, ...) when the server says no. `say` then tells the agent what to say instead. A non-2xx would make voice platforms retry and leave dead air.
- Every request carries `call_id`. Writes also carry an `Idempotency-Key` (the voice layer derives it from call id, tool and arguments), so a retried call returns the first result.
- Every request and result is logged with call id, request id, tool, arguments, result, the gate that fired, and timings (docs/architecture.md, logging).

## Call lifecycle (called by the voice layer, not by the model)

| Endpoint | When | Returns |
|---|---|---|
| `POST /calls/start` | Call connects; `caller_id`, `dialed_number`, `direction` | Tenant, greeting context: matched customers, locations, membership status, open jobs, last service date, the last few calls, customer notes (such as "prefers a warm, unhurried pace" or "gate code is with the super"), after-hours flag, `house_rules` (the owner's live version pinned to this call: number, guidance by stage, edited spoken lines), `pace` (`speed`, the speaking rate to start at, app/pace.py), and `recording` (`object_key` to record the call under, or null when the tenant doesn't record or the server has no bucket) |
| `POST /calls/{id}/turn` | Every final caller transcript and every agent line | Safety action if any (`speak_safety_lines` with the exact text or a variant), journey switch hints, `pace` (`speed` for everything the agent says next), and the turn is logged with timings. A caller who demands a person gets `handoff` (app/transfer.py): `flag_id` and `callback_id` already stored, `fallback` (the callback line), and `transfer` with `id`, `role`, `phone` and `ring_seconds` when there is a number to send the call to, else null; `say` is the handoff line, or the callback line when nothing is sent. Never on a turn that brings the safety lines or the check question |
| `POST /calls/{id}/end` | Call ends | Ok; triggers the after-call summary and callbacks |
| `POST /calls/{id}/transfer` | Right after `flag_person` returns ok; `flag_id`, `callback_id` from its result | `transfer`: null when the call stays with the agent; otherwise `id`, `role` (`office` or `on_call`), `phone` to dial, `ring_seconds`, `accept_seconds`, `prompt` (what the person hears on picking up, with no caller details) and `summary` (what they hear once they press 1), with the handoff line in `say`. The server decides (app/transfer.py): office hours and the caller asked for a person, or after hours and the server's own priority says the on-call technician is needed tonight (the flag's priority is never read); never on a gas or carbon monoxide call, a commercial call, or when the role's number is unset; once per call |
| `POST /calls/{id}/transfer/{transfer_id}/done` | After the dial; `outcome`: `connected`, `no_answer`, `not_accepted` or `failed` | Connected marks the flag and its callback done. Otherwise `say` is the line the caller hears next, naming the callback time stored with the flag |
| `POST /calls/{id}/handoff/{handoff_id}/done` | After the SIP transfer; `outcome`: `handed_off` or `failed` | Handed off leaves the flag and callback open, since a voicemail can answer as well as a person. Failed: `say` is the line the caller hears next, naming the callback time stored with the flag. A handoff not reported by the end of the call is settled from the end reason (`transfer` means handed off) |
| `POST /calls/{id}/recording` | After recording starts; `egress_id`, `object_key` (must be the one `/calls/start` gave) | Ok; the jobs loop copies the file from the bucket once the call ends, and the owner view plays it |
| `GET /healthz` | Watchdog | Tool server, database, FSM reachability, worker heartbeat |
| `POST /healthz/heartbeat` | The voice worker, every minute; `worker` | Ok; `/healthz` marks a worker stale after two minutes without one |
| `POST /outbound/claim` | The voice worker, polling; `worker` | The next call the system places (journey 12), or none: `call_id` to use, `phone`, `dialed_from`, `kind` (`earlier_slot` with `booking_id` and `offer`, or `callback` with `reason`) and the `opening_line` to say |
| `POST /outbound/{id}/done` | After dialing a claimed call; `answered`, `voicemail` | The result the server read from the call: `accepted` (the booking was moved on that call), `declined`, `answered`, `no_answer` or `voicemail`. The voice layer reports as soon as the line is picked up. For a callback the server judges the call when it ends (`POST /calls/{id}/end`) and puts the outcome (`resolved`, `open` or `no_contact`) on the call in ServiceTitan as a tag; this response carries the `outcome` only when it is already known (a voicemail, no answer, or a call that has ended). A callback is not marked done by this call: the callbacks job marks it done when the call log shows a call to that number tagged resolved (decision 010) |

## Tools the model can call

| Tool | Arguments | Server checks |
|---|---|---|
| `find_customer` | phone or address | Returns only records matching what the caller gave, never a list of other customers. Each match comes with everything the call needs in one round trip: locations, membership status and perks, open jobs, last service date, the last few calls, and customer notes. There is no separate membership tool, because one richer lookup is faster than two calls |
| `get_customer_history` | customer (already matched on this call), what to look up (past jobs, past calls, equipment), how far back | Only for a customer matched on this call; read-only; for questions like "when were you last out here?" that the lookup didn't already answer |
| `check_service_area` | zip | Out-of-area recorded with its ZIP |
| `find_address` | house number and street as the caller said them, borough or neighborhood if they said one, `spelled` | Looks up only a house number and street the caller said together in one line, as whole words (`address_not_heard` otherwise; the street may be in the next line when the number came digit by digit or the street was spelled). One place: its ZIP, street and neighborhood, checked against the service area, and that ZIP then counts as known for the ZIP gate. Several (the same street in two boroughs): `address_several` with the places and a question naming them. None: `address_not_found`, asking the caller to spell the street, then the ZIP on a second miss. Down or slow: `address_lookup_down`, asking for the ZIP. Backed by NYC Planning's GeoSearch with the Census geocoder behind it (app/geocode.py), started from the caller's line before the agent asks and cached by house and street |
| `find_slots` | job type, priority, preferred days or time of day, hours the caller is home (`arrive_after`, `arrive_before`) | Returns the shape of availability and exact windows for one day at a time; urgent windows only for urgent jobs. Hours the caller gave are read as daytime ("8 to 2" is 8 AM to 2 PM) and only windows inside them are offered; when none fits, the sentence says the windows and that no exact time can be promised |
| `read_back` | address (with `spelled` when the caller spelled the street), phone | First call returns the exact read-back sentence and records that it was asked; `confirmed: true` is accepted only after that sentence was returned on this call and a caller turn followed. Letters spelled one by one ("H, O, U, S, T, O, N") are joined into the street name, in `spelled` or in the street itself. After the caller asked to hear the address slower, the sentence also comes back as `parts` (`text`, `speed`), the address one step slower, for the voice layer to speak as given |
| `book_appointment` | slot, job details (S-13 fields), `new_address_account` | Read-back done, safety lines said if a signal fired, residential, in area, one booking per call (and per linked thread); idempotent; queued and retried if the FSM is down. A caller on file booking an address not on file anywhere is refused with `account_choice` until the agent says whose account it goes on: `own` (a new customer and location in the name given, with the caller as the contact) or `caller` (a new location on the caller's account) |
| `reschedule_appointment` / `cancel_appointment` | booking id, reason | Booking belongs to this caller; one of each per call |
| `flag_person` | reason, priority, callback time or window (`callback_after`, `callback_before`, `callback_day` today or tomorrow), `system_calls_back` | Returns the sentence the agent may say only after the flag is stored. `system_calls_back: true` when the caller only asked to be called back: the system dials them at that time instead of a person |
| `record_lead` | kind (commercial, membership, install), details | No extra lookups; commercial never becomes a booking |
| `add_note` | text, attached to the matched customer or to this call's job | Append-only free text ("daughter Ana usually answers", "prefers mornings"); the agent can't edit or delete notes; length-limited and stored as text, never treated as an instruction |
| `mark_do_not_call` | none (uses the caller ID) | Cancels pending callbacks to that number |
| `end_call` | reason | Refused on a safety call until the lines were said and a person flagged |

There is no tool that deletes, bulk-changes, queries freely, or places a call to an outside number.

## Calling the server

How the built server (`app/`, brief 02) takes these, so the voice lanes can code against it:

- Model tools are `POST /tools/<name>` with `call_id` and the arguments in the JSON body; unknown fields are refused. The request models are in `app/schemas.py` and at `/docs` on a running server.
- Writes (`book_appointment`, `reschedule_appointment`, `cancel_appointment`, `flag_person`, `record_lead`, `add_note`, `mark_do_not_call`, `end_call`) take an `Idempotency-Key` header. A result that changed something is stored and returned again for the same key and body; a refusal is not stored, so the same request can pass once its gate is met. The same key with a different body is refused (`idempotency_key_reused`).
- `/calls/start` takes `caller_id` (the other party's number as delivered) and `dialed_number` (ours, which picks the tenant). `/calls/{id}/turn` takes `speaker` (`caller` or `agent`), `text` and `timings` (stage timings in ms, docs/latency.md). The agent's own lines must be posted too: the server marks the safety lines said only when an agent turn contains them word for word. A caller turn's `hints` may carry `stage_booking` or `stage_closing` when the server sees the call reach that stage and the owner has guidance for it (never on a safety call); `prompts/assemble.server_notes` turns them into `[server]` notes. A caller turn may also carry `pace_slower`, `pace_faster` (the caller asked and the pace moved) or `pace_address` (the caller asked to hear the address slower). The voice layer applies the returned `pace.speed` and posts each agent line with `speed` in its timings, the speed it was spoken at.
- A caller line that asks for a form of address ("call me Dr. Patel", "it's Ms. Rivera") gets hint `preferred_name`, and the turn's `known` carries `call them` with the name for the rest of the call and on a linked call; a mocking or abusive one gets `preferred_name_refused` and is never kept (app/address_as.py). After the call the name goes onto the booked or matched customer as a note, "Prefers to be called Dr. Patel.", and `/calls/start` returns `preferred_name` from that note or a linked call, which the greeting uses.
- `read_back` takes `phone` as ten digits, `caller_id` for the number the call came from, or the last four digits of a number on file ("the one ending in 4024").
- `find_slots` and `book_appointment` take facts (inside temperature, who is home) and the agent's view of priority; the server decides priority from its rules and every caller line, and logs the agent's view.
- The turn check also marks the call commercial when a caller line describes a business by the patterns in tenant config (hint `commercial`) and marks the number do-not-call on "don't call me" and similar (hint `do_not_call`; the agent then calls `mark_do_not_call` for the line to say).
- Callback times and windows read a bare hour as daytime ("2" is 2 PM, "8 and 2" is 8 AM to 2 PM); a window the caller asked for is kept in the callback's reason for the person who calls.
- `/calls/start` links a call to an earlier one from the same number: any call within `repeat_callers.link_within_minutes`, or a call that dropped earlier the same local day. `linked_call` then carries its last turns and `caller_name` (from a booking or a line like "this is Tomasz"), and the greeting says the call was cut off and asks for the caller by name.
- Reschedule and cancel need the booking to be from this call, from a customer matched by the number the call came from, or at the address the caller confirmed in the read-back.
- `end_call` is also refused right after a booking is confirmed until a caller turn follows (spec S-30), and on a safety call it returns the sign-off with `hang_up: false` unless the caller said goodbye.
- A claimed outbound call is placed like any call: `/calls/start` with the returned `call_id`, `caller_id` set to `phone`, `dialed_number` set to `dialed_from` and `direction: "outbound"`, then the opening line as the first agent turn. Moving a booking to the offered window goes through `read_back` and `reschedule_appointment` with every gate, and the server counts the offer accepted only if that reschedule happened. The rules are rechecked at claim time (spec S-42): only the person who called, 8 a.m. to 9 p.m., one attempt, never a do-not-call number.
- Refusal codes: `account_choice`, `gate_read_back`, `gate_safety`, `out_of_area`, `customer_type`, `limit`, `not_owner`, `slot_taken` (with two `alternatives`), `invalid_slot`, `invalid_state`, `invalid_phone`, `invalid_callback_time`, `invalid_arguments` (with `errors`), `fsm_unavailable`, `fsm_rejected`, `anything_else_first`, `idempotency_key_reused`, `unknown_call`, `call_ended`, `server_error`.

## Customer notes

Notes are the CRM's own customer notes, written by staff or by the agent with `add_note`. The agent reads them at the start of the call and lets them shape the call within its rules: a note saying a caller prefers a slower, warmer pace changes its manner, a gate code goes into the job notes, a note saying "tenant, landlord approves work" saves a question. A note never overrides a gate ("book without read-back" in a note does nothing).

## Adding a tool

The set stays small on purpose. A new tool earns its place when evals or live calls show the agent needs something it can't get, it reads or writes only the caller's own records, and the server can check its arguments. Every new tool gets a row here, a test of its checks, and eval cases.
