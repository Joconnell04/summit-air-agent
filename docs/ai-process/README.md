# How this was built with AI

Built with Claude Code, mostly by voice through transcription. The structure is meant to make sure nothing said is lost and every AI change can be traced.

- **Sessions by phase.** Setup, design, build (parallel lanes), test and tune, demo prep. Each new session starts from a prompt kept in `briefs/`.
- **Co-authoring for the documents that define the product.** Claude drafts, Jackson reacts by voice, Claude revises; each round is logged in `coauthoring.md` with the feedback verbatim and the commit.
- **Decisions.** Jackson's calls are prepared as short readouts in `/docs/decisions/` and recorded as one entry each in `/DECISIONS.md`, linked to the discussion that produced it. `design-trail.md` lists them in order so the reasoning can be followed end to end.
- **Set aside on purpose.** `/docs/later.md` holds everything deferred, walked before V1 is done.
- **Side research.** `/explore` runs a background research agent with a fixed template; results in `/docs/explorations/`.
- **Agent loops with verification.** Build agents work on branches from a brief. A pre-commit hook runs the fast tests, CI runs everything on each pull request, a ratchet blocks a lower test count, and a read-only reviewer agent checks the change against its brief. Two failures escalate to a needs-decision issue.
- **A design system, drawn before it was built.** Five directions for the owner view were drawn as live pages on a Claude design canvas, then two mixes of the chosen pair. Jackson picked one (DECISIONS.md 016), and the pages were built on a full design system: tokens, components, a live specimen at `/owner/design` and `/docs/design-system.md`. The built pages were captured back onto the canvas for markup; two rounds of Jackson's sticky notes came back as changes (DECISIONS.md 017 and 018), each checked by a self-review and a separate reviewer agent. The system is then saved to the Claude account as a design system (DECISIONS.md 074), so later sessions and any new page start from the same tokens and rules; `make design-export` rebuilds that copy from the code.
- **Transcripts.** Exported from the design sessions into `transcripts/`.
- **Considerations.** A running list in `/docs/considerations.md`, triaged into scope during design and now closed. New ideas, and anything set aside, go in `/docs/later.md` (`/consider`).
- **Lanes.** Every build lane has an issue labeled `agent` that its pull requests close; `make lanes` writes `docs/ai-process/lanes.md` from them.
- **Phases.** `phases.md` is the route; Claude proposes each next step and Jackson says go.

## Files here

| File | What it is |
|---|---|
| [brief-next.md](brief-next.md) | The current brief for Jackson: what needs him, what's live, what's open, what was decided without him |
| [lanes.md](lanes.md) | Every build lane with its issue, pull requests and decisions, generated by `make lanes` |
| [phases.md](phases.md) | The route, phase by phase, ticked as steps close |
| [design-trail.md](design-trail.md) | Every decision in order, one row each |
| [coauthoring.md](coauthoring.md) | Each co-authoring round, with Jackson's feedback verbatim |
| [playbook.md](playbook.md) | How each session runs |
| [briefs/](briefs/) | The prompt each early build lane started from |
| [past-briefs/](past-briefs/) | Earlier briefs for Jackson, kept as written (`brief-after-check-ins.md` is the one before this) |
| [transcripts/](transcripts/) | Exported design-session transcripts |

## Finished branches

A build or fix branch is kept as a tag once its pull request merges: `archive/<branch>` (for example `archive/build/tool-server`), then the branch is deleted, so the branch list shows only work in progress and every lane's history stays on GitHub under Tags.
