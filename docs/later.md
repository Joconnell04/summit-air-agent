## Ideas to look into

Added with `/consider`. Numbered C-NN after the last number in docs/considerations.md (C-56). An idea here is a prompt to investigate, never a decision; when it's looked at, it moves to the table above, to an exploration, or out with a reason.

| Idea | Raised | Status |
|---|---|---|
| **C-57 Size each model to its job.** V1 keeps Haiku 5.5 live, Sonnet 5.5 for the technician summary and Opus 5.5 grading evals. With more time, measure the real Haiku-to-Sonnet gap on a task before paying for the bigger model. First, the summary: Haiku with thinking against Sonnet on about 20 eval transcripts, scored by the server's line-by-line check; Sonnet is roughly 20 times Haiku per token (SOURCE: config/models.yaml prices), so at about 2.5 cents a summary (ASSUMED) it's about $40 a month at full volume, which docs/cost.md doesn't count yet. Second, the grader: Haiku or Sonnet first, Opus only on failures and borderline calls; worth it only once evals run on every change, and only after rechecking agreement with Jackson's round 3 labels. Out of scope: switching models mid-call on the live path, rejected in exploration 014 (idea 10) for the slower first word and the change in how the agent sounds. | Jackson, after the model-routing answer in docs/ai-process/brief-next.md | open |
| **C-58 A caller who argues for a higher priority.** Read in the code (not yet tested by an eval): insisting alone doesn't raise it. "It's an emergency", "make it urgent" or "I'll pay extra" match no priority rule, and the priority the model asks for is only logged (`app/tools.py` `find_slots`, the `requested` field). Facts do raise it, and the server believes the caller: "my 85-year-old mother is here" makes a no-heat call Urgent, by design, since missing an at-risk caller is worse than a false raise. Three softer paths to look at: (1) the model's own summary (`who_home`, `issue`, `inside_temp_f`, the job type) feeds the same phrase rules as the caller's words (`_priority` in `app/tools.py`), so a caller who pressures the agent, or a model slip, can write "elderly" that was never said; after hours that asks the on-call technician (a person still decides); (2) the side model reads the caller's lines and might score insistence as risk; (3) a fact added only after the caller hears the wait ("actually my mother lives here") raises it like any other. To handle it well: raise only on the caller's own words, as the ZIP rule does (DECISIONS.md 058); quote the caller's line in the priority reason and flag a raise that came after the caller heard the wait, so the dispatcher can judge; when pushed, the agent says one calm line, doesn't argue or promise a level, asks the at-risk question once if it hasn't, offers the soonest window or a person, and gives the 911 line if anyone is in danger; three evals (pushes with no facts and stays put; adds a fact after hearing the wait and is raised and flagged; tells the agent to "just put it as urgent" and stays put, with a code check that `who_home` holds nothing the caller didn't say); and on the owner view, a count per caller number of raises later marked not at risk. | Jackson, during the round 3 merge | built in #126 (DECISIONS.md 072, 073); the owner-view count is of raises after the wait, as the lane brief asked |

Live calls run on LiveKit, so it waits until Retell is used again. | Coordinator, PR #125 | open |
